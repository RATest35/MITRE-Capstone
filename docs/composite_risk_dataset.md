# Composite Risk GraphML Dataset

def add_composite_score(G):
    for n, data in G.nodes(data=True):

        risk = 1
        bet = data.get("weighted_betweenness", 0)
        pr = data.get("pagerank", 0)

        importance = bet + pr

        data["importance"] = importance
        data["composite_score"] = risk * importance

    return G

## 1. 概要

`examples/gnn/composite_risk.graphml` は、IP アドレス間の通信を有向グラフとして表現した GraphML データセットである。

- ノード: IP アドレス
- エッジ: 通信の向き
- エッジ重み: 通信量
- ノード属性: 通信量、中心性、複合リスク指標

このデータセットは、ネットワーク上で相対的に重要または高リスクに見える IP を、通信量とグラフ構造の両方から分析するための入力データとして使える。

## 2. ファイル情報

- データファイル: `examples/gnn/composite_risk.graphml`
- 形式: GraphML
- グラフ種別: 有向グラフ
- ノード数: 23,511
- エッジ数: 66,863

ノード ID は IP アドレス文字列であり、内部ネットワークと思われるプライベート IP と外部公開 IP が混在している。

- プライベート IP ノード数: 1,927
- パブリック IP ノード数: 21,584

例:

- プライベート IP: `10.200.7.4`, `10.200.7.5`, `10.200.7.8`
- パブリック IP: `103.224.182.252`, `103.235.247.8`, `103.30.232.147`

## 3. 何を表しているデータか

このグラフでは、各ノードが 1 つの IP アドレスを表す。
エッジは送信元 IP から宛先 IP への通信を表し、`flow` にその通信量が格納されている。

ノードには、単純な入出力流量だけでなく、以下のようなグラフ分析指標が含まれている。

- `weighted_betweenness`
- `pagerank`
- `importance`
- `composite_score`

そのため、このデータセットは単なる通信ログの集約ではなく、通信グラフに対して中心性分析やスコアリングを実施した後の派生データと考えられる。

## 4. ノード属性

GraphML のキー定義上、ノード属性は次の名前を持つ。

| 属性名 | 型 | 意味 |
| --- | --- | --- |
| `in_flow` | `long` または `double` | 受信流量 |
| `out_flow` | `long` または `double` | 送信流量 |
| `flow_loss` | `double` | 入出力差分に相当する損失量 |
| `weighted_betweenness` | `double` | 通信量を考慮した媒介中心性 |
| `pagerank` | `double` | PageRank |
| `importance` | `double` | ノード重要度 |
| `composite_score` | `double` | 複合リスクスコア |

### 4.1 属性の実使用状況

ノード属性には、同じ属性名に対して複数のキーが定義されている。

- `in_flow`: `d0` と `d7`
- `out_flow`: `d1` と `d8`

実データ上の使用回数は次の通り。

| キー | 属性名 | 使用ノード数 |
| --- | --- | --- |
| `d0` | `in_flow` | 725 |
| `d7` | `in_flow` | 22,786 |
| `d1` | `out_flow` | 6,499 |
| `d8` | `out_flow` | 17,012 |
| `d2` | `flow_loss` | 23,511 |
| `d3` | `weighted_betweenness` | 23,511 |
| `d4` | `pagerank` | 23,511 |
| `d5` | `importance` | 23,511 |
| `d6` | `composite_score` | 23,511 |

このことから、データ生成過程で `in_flow` と `out_flow` の型が一貫しておらず、整数型と浮動小数型が混在した可能性が高い。

### 4.2 `importance` と `composite_score`

全 23,511 ノードについて確認したところ、`importance` と `composite_score` は完全に同一値である。

そのため、このファイル単体を見る限り、実質的な最終スコアとして使うべき値は `composite_score` だけで十分である。

## 5. エッジ属性

エッジ属性は次の 2 つである。

| 属性名 | 型 | 意味 |
| --- | --- | --- |
| `flow` | `long` | 送信元から宛先への通信量 |
| `distance` | `double` | 距離または重み付け用の値 |

### 5.1 `distance` の特徴

全 66,863 エッジで `distance` は `999999999.9999999` に固定されている。

したがって、このデータセットでは `distance` は実質的に情報量を持っておらず、分析時には定数列として扱ってよい。

## 10. このデータセットから読み取れること

このデータセットは、次のような用途に向いている。

- 高リスク IP のランキング
- 通信ハブの抽出
- ボトルネックや中継点の検出
- GNN やグラフ分析アルゴリズムの入力
- 通信量と中心性を組み合わせた異常候補探索

特に、単純な流量だけではなく中心性を含んでいるため、「大量通信を行うノード」と「構造上重要なノード」を分けて観察できる。

## 11. 解釈上の注意

### 11.1 元データの業務文脈は不明

このファイル単体からは、どのログソースから生成されたか、どの期間の通信を集計したか、どのシステムを対象にしたかは分からない。

### 11.2 `flow_loss` の定義はファイル単体では明示されていない

実データを見ると、`flow_loss` は多くのノードで `in_flow + out_flow` に等しい。
そのため、一般的な「損失」というより、総トラフィック量に近い派生量として扱われている可能性がある。

### 11.3 属性名の重複に注意が必要

`in_flow` と `out_flow` は複数キーに分かれているため、GraphML を読む実装によっては片方しか取得できない可能性がある。
読み込み時にはキー名ではなく、実際のデータ値の存在を見て正規化する方が安全である。

### 11.4 `distance` は特徴量として使いにくい

`distance` は全エッジで一定値なので、学習や分析の特徴量としては有効ではない。

## 12. 読み込み例

Python と `networkx` で読む最小例を示す。

```python
from pathlib import Path

import networkx as nx


graph_path = Path("examples/gnn/composite_risk.graphml")
graph = nx.read_graphml(graph_path)

print(graph.is_directed())
print(graph.number_of_nodes())
print(graph.number_of_edges())

sample_node = "10.200.7.217"
print(graph.nodes[sample_node])
```

ノード属性の型が揃っていないため、分析前に `in_flow` と `out_flow` を明示的に `float` へ揃える前処理を入れる方がよい。

## 13. 要約

`composite_risk.graphml` は、IP 通信グラフに対して中心性指標と複合リスクスコアを付与したネットワーク分析用データセットである。
高スコアノードは一部の内部セグメントに集中しており、通信量の偏りと構造的重要性の両方が反映されている。
一方で、属性型の不整合や `distance` の定数化など、前処理時に注意すべき点もある。
